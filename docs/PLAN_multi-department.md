> מסמך תכנון. נכתב לפני נגיעה בקוד, כנקודת-ייחוס לצוות (נאור · אלינה · ענבל).

## 1. המטרה והעיקרון

הדשבורד של איתי ("מפת ההכשרה — פוליטיקה וממשל") הוא **בסיס מצוין**, אבל בצורתו הנוכחית הוא כלי של **מחלקה אחת**: כל אוצר-המילים התחומי (מיומנויות, משפחות הוגים, קהילות, לוח-שנה) קשיח בתוך `index.html`. מחלקה חדשה = לשכפל את הקובץ ולערוך JavaScript.

**המטרה:** להפוך את `index.html` ל**מנוע גנרי** שאינו יודע דבר על פוליטיקה-וממשל, ולהוציא את כל הידע התחומי ל**קונפיגורציה** (`config.json`) נפרדת לכל מחלקה. אז:

- מחלקה חדשה = תיקייה חדשה עם 3 קבצי טקסט. **אפס שינוי קוד.**
- תחזוקה שוטפת (רכז/ת מחלקה) = עריכת CSV ו-config, לא JS.
- תיקון/שיפור בלוגיקה = מקום אחד, חל על כל המחלקות בבת-אחת.

**עיקרון מנחה:** הקוד לא מכיר שום שם של מיומנות, הוגה או קהילה. הכול מגיע מה-config או מה-CSV.

## 2. המצב היום (מה קשיח בקוד)

הבסיס עצמו נקי: קורס = שורה ב-`courses.csv`, מטלה = שורה ב-`tasks.csv` מקושרת דרך `course_id`, ו-6 תצוגות (ציר זמן · גרף התפתחות · מטריצת מיומנויות · מפת הוגים · קהילות וסוגות · רשימה). **מודל הנתונים הזה נשאר** — הוא כבר גנרי במהותו.

מה שצריך לצאת מהקוד (כולם קבועים ב-`index.html`):

| # | מה | כיום | הבעיה בהכללה |
|---|-----|------|---------------|
| 1 | `SKILLS` + `SUB` | 8 מיומנויות ורכיבי-המשנה שלהן | תחומי לגמרי — לכל מחלקה אחר |
| 2 | `DIMS` | 5 ממדים (עומק/היקף/הכוונה/אופי/קהל) + הערכים | חלקם אולי משותפים, חלקם לא |
| 3 | `THINKER_FAM` + `FAM_ORDER` + `FAM_LABEL` + `FAM_COLOR` | טבלת שיוך ידנית: הוגה ← משפחה | **הכאב הגדול** — טבלה ידנית שלא תשתכפל יפה |
| 4 | `COMMUNITIES` + `COMM_COLOR` | קהילות העשייה + צבעים | תחומי |
| 5 | `SEMS` | לוח-שנה (תאריכים, שבועות, חופשות) קשיח לתשפ"ו | משתנה כל שנה, ולכל מוסד |
| 6 | `semIndex` | מניח תואר תלת-שנתי, שנים א׳/ב׳/ג׳ | תוכניות שונות (שנתיים? ארבע?) |
| 7 | אפשרויות מסנן "סוג תוצר" | קשיחות ב-HTML (`<select>`) | שאר המסננים נבנים מהנתונים — אי-עקביות |

**באג עקרוני לתיקון אגב כך (#3 נגזרת):** ההתאמה הוגה↔מקור משתמשת ב-`includes()` (substring). זה שביר — ייתן התאמות-שווא (למשל שם קצר שמוכל בתוך מחרוזת אחרת) והחמצות. בהכללה צריך התאמה מפורשת.

## 3. הארכיטקטורה המוצעת

### מבנה תיקיות
```
/  (repo)
├── index.html              ← המנוע הגנרי. משותף לכל המחלקות.
├── assets/                 ← (אופציונלי) CSS/JS משותפים אם נפצל
├── departments/
│   ├── political-science/
│   │   ├── config.json     ← אוצר-המילים התחומי (טבלה 2)
│   │   ├── courses.csv
│   │   └── tasks.csv
│   ├── sociology/
│   │   ├── config.json
│   │   ├── courses.csv
│   │   └── tasks.csv
│   └── ...
└── index.html?dept=political-science   ← הדשבורד נטען עם פרמטר מחלקה
```

המנוע קורא `?dept=<slug>` מה-URL, טוען `departments/<slug>/config.json` ואז את שלושת הקבצים. ברירת מחדל: מסך-פתיחה שמציג את רשימת המחלקות הקיימות (נבנית מ-`departments/index.json` או מרשימה ב-config עליון).

> הערה: אפשר גם להתחיל פשוט יותר — `config.json` לצד ה-CSVים בשורש, בלי תיקיית `departments/` — ולפצל רק כשמגיעה המחלקה השנייה. ראו שלבי המעבר (§5).

### סכמת `config.json` (טיוטה)
```jsonc
{
  "department": { "slug": "political-science", "name": "פוליטיקה וממשל", "year": "תשפ\"ו" },

  "program": {
    "years": ["א׳", "ב׳", "ג׳"],        // קובע את semIndex ואת צירי הגרף
    "yearColors": { "א׳": "#0f6e56", "ב׳": "#7a4bab", "ג׳": "#b9540e" }
  },

  "calendar": {                          // מחליף את SEMS
    "א": { "label": "סמסטר א׳ · ...", "weeks": 13, "start": [2025,9,26], "breaks": [] },
    "ב": { "label": "סמסטר ב׳ · ...", "weeks": 16, "start": [2026,2,15], "breaks": [3,4] }
  },

  "skills": [                            // מחליף SKILLS + SUB + SK_COLORS
    { "name": "ניתוח מקורות", "color": "#0f6e56",
      "subs": ["זיהוי הטענה המרכזית", "פירוק מבנה הטיעון", "..."] }
  ],

  "dimensions": {                        // מחליף DIMS
    "depth":  { "label": "עומק העיבוד", "ordered": true,
                "vals": ["חילוץ ופירוק", "פרשנות", "קישור לידע אחר", "ביקורת והכרעה", "יצירה מקורית"] },
    "scope":  { "label": "היקף התוצר", "ordered": true, "vals": ["רכיב בודד", "תוצר חלקי", "תוצר שלם"] },
    "guide":  { "label": "רמת ההכוונה", "vals": ["פתוח", "מכוון", "מובנה מלא"] },
    "inquiry":{ "label": "אופי המחקר", "vals": ["תיאורטי־פילוסופי", "אמפירי", "משולב", "לא רלוונטי"] },
    "aud":    { "label": "קהל יעד", "vals": ["אקדמי", "חברה אזרחית", "..."] }
  },

  "families": [                          // מחליף FAM_* + THINKER_FAM
    { "key": "קלאסי", "label": "הגות קלאסית ונורמטיבית", "color": "#0f6e56",
      "thinkers": ["אפלטון", "אריסטו", "הובס", "..."] }
  ],

  "communities": [                       // מחליף COMMUNITIES + COMM_COLOR
    { "name": "מחקר אקדמי", "color": "#7a4bab" }
  ],

  "taskTypes": ["ניתוח טקסט", "עבודה", "מבחן", "הצגה"]   // מחליף את ה-<select> הקשיח
}
```

**הכרעת-מפתח ל-#3 (משפחות הוגים):** משייכים הוגה למשפחה **בתוך ה-config** (רשימת `thinkers` תחת כל משפחה), במקום טבלת-הפוך ידנית בקוד. המנוע בונה את מיפוי ההפוך (`thinker → family`) בזמן-ריצה. יתרון: כל מחלקה מתחזקת רק את ההוגים שלה, במקום אחד, ליד שאר ה-config. חלופה עתידית: עמודת `family` ישירות ב-`courses.csv`/`tasks.csv` — אבל זה מפזר את הידע; עדיף ריכוז ב-config.

## 4. מה **לא** משתנה

- מודל ה-CSV (courses/tasks) — נשאר. אולי נוסיף עמודות אופציונליות, לא נשנה קיימות.
- שש התצוגות והרעיון המרכזי (הפער בין "מה מוצהר" ל"מה מתורגל", מושג נטוש, קהילה יחידה).
- חווית העריכה של הרכז/ת: לחיצה על קובץ ב-GitHub → עריכה → commit (כמתואר ב-README).
- העיקרון של "היעדר הוא ממצא" — קהילה/מיומנות עם 0 מטלות עדיין מוצגת.

## 5. שלבי מעבר (incremental, בלי לשבור)

כל שלב עומד בפני עצמו ומשאיר דשבורד עובד.

- **שלב 0 — תיעוד (המסמך הזה).** ✅
- **שלב 1 — חילוץ config, בלי לפצל תיקיות.** מוציאים את טבלה 2 מ-`index.html` ל-`config.json` בשורש. המנוע קורא ממנו. פוליטיקה-וממשל עובד **בדיוק** כמו היום. כאן גם מתקנים את באג ה-`includes()`. _זה "הריפקטור במקום" שדיברנו עליו — השלב הראשון המעשי._
- **שלב 2 — תמיכה בריבוי מחלקות.** מוסיפים `?dept=`, מעבירים לתיקיית `departments/political-science/`, מסך-פתיחה לבחירת מחלקה.
- **שלב 3 — מחלקה שנייה (פיילוט).** מוסיפים `config.json` + CSVים למחלקה אחת נוספת. כאן מתגלים כל ההנחות הסמויות שנותרו — וזה הזמן הנכון לגלות אותן.
- **שלב 4 — ליטוש והכללת-תוכן.** ווקflow הוספת מחלקה (תבנית `config.json` ריקה + README), ואולי כלי-עזר לייצור ה-CSV מתוך ניתוח סילבוסים (כמו שנעשה לפוליטיקה-וממשל).

## 6. שאלות פתוחות לצוות

1. **מקור ה-CSV:** ה-README מזכיר ש"השורה מגיעה מוכנה מפרויקט הניתוח". מהו התהליך? האם ההכללה צריכה לכלול גם את שלב הניתוח (סילבוס → שורות CSV), או שזה נשאר ידני/חיצוני לכל מחלקה?
2. **אחידות הממדים:** האם 5 הממדים (עומק/היקף/הכוונה/אופי/קהל) ו-8 המיומנויות אמורים להיות **משותפים לכל המחלקות** (מסגרת פדגוגית אחידה של המרכז), או שכל מחלקה מגדירה משלה? זה משנה אם הם ב-config-לכל-מחלקה או ב-config-עליון משותף.
3. **תוכניות לימוד שונות:** תואר דו-מחלקתי, שנתיים מול שלוש, קורסי בחירה — עד כמה להכליל עכשיו מול "כשנגיע לזה"?
4. **אירוח:** היום זה GitHub Pages של repo יחיד? ריבוי מחלקות באותו repo, או repo לכל מחלקה? (ממליצה: repo יחיד, תיקיות — פשוט יותר לתחזק ולתקן-פעם-אחת.)
5. **הרשאות:** מי עורך את ה-config של מחלקה? רכז/ת המחלקה, או רק הצוות המרכזי?
